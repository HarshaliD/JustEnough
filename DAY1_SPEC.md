## 3. Frozen taxonomy, actions and policy floor

Categories (16): account_identifier, government_id, person_name, counterparty_name, address, contact,date_of_birth, internal_id, employer, merchant, amount, balance, transaction_date, salary_component,medical_value, clause_text. New categories need an entry in Section 18.

Actions (exactly one per detected category):
| Action | Meaning |
|---|---|
| KEEP | Exact value is required for the task |
| DROP | Not required; remove completely |
| MASK_PARTIAL | Only part is needed (e.g. last 4 digits) |
| GENERALIZE | Broader form is enough (e.g. age band for DOB) |
| PSEUDONYMIZE | Identity not needed, but occurrences must stay linkable |
| AGGREGATE | Totals, counts or groups are enough |

Planner rules:
1. For each detected category, decide whether the exact value is needed for this task.
2. Not needed -> DROP. Reduced form needed -> least-data action among MASK_PARTIAL, GENERALIZE,
   PSEUDONYMIZE, AGGREGATE. KEEP only when the exact value is required.
3. No fixed category -> action defaults (except the policy floor). The same category may get different
   actions for different tasks.
4. Use only what is in the skeleton.
5. The planner decides; deterministic code transforms.

Policy floor (overrides the planner): government_id, full account numbers and full card numbers must be
DROP or MASK_PARTIAL, never KEEP. A floor violation is a planner failure even if the answer is correct.
(Same lists as AGENTS.md. If they ever differ, stop and fix both.)

Principle: remove everything the task does not need, not as much as possible.

## 6. Ground truth
File: ground_truth/labels.json (human-approved, immutable). Agents may only write ground_truth/proposed_labels.json.

Per case, per category:
```json
{  
  "case_id": "BS-1-A",
  "categories": {
    "merchant":           {"required": true,  "acceptable_actions": ["KEEP"], "ambiguous": false},
    "account_identifier": {"required": false, "acceptable_actions": ["DROP", "MASK_PARTIAL"], "ambiguous": false},
    "counterparty_name":  {"required": false, "acceptable_actions": ["DROP", "PSEUDONYMIZE"], "ambiguous": true}
  }
}
```
Rules:
- A category is `required` if removing it could change the task answer.
- Use a SET of acceptable actions, not a single action.
- Genuinely ambiguous categories are flagged, excluded from agreement scoring, but counted and reported.
- The same model family that runs the planner must not write the labels. A human writes or signs every label.

## 7. Experiment pipeline
1. Extract text (pdfplumber for PDFs).
2. Detect: Sensitive Data Protection plus custom patterns (UPI handle, IFSC, Indian phone, masked account). Record recall.
3. Build the skeleton (typed placeholders for detected values).
4. Planner: skeleton + task + action semantics + policy floor -> structured plan (JSON). Retry once on schema failure.
5. Apply the plan with deterministic code. KEEP preserves the value; the other five actions perform their specified transformations.
6. Equivalence check on the selected cases (Section 8).
7. Compare plan to labels (secondary).
8. Aggregate metrics, attribute failures, write report.

Run settings (recorded in every run log): model: resolved from JUSTENOUGH_MODEL environment variable, temperature 0, runs per case 3, seed 8.
Detection fallback: if the detection API is blocked, run regex-only and label the whole run "regex-only".

## 8. Equivalence check (primary metric)
Run on at least 10 cases: at least one per document type and at least 2 trap cases. [FILL case IDs]

Protocol per case:
1. Run the task on the ORIGINAL with a structured output schema -> R0. Run twice; if the two disagree, mark the case
   "unstable", compare by rubric, and report unstable cases separately.
2. Run the same task on the MINIMIZED representation -> R1.
3. Compare R0 and R1:
   - numbers: within 0.5% relative tolerance
   - lists: set equality
   - free text: all key facts in a short human-written rubric are present (LLM judge only as a last resort, stated in the report)

## 9. Metric definitions
- Answer preservation = cases where R1 matches R0 / cases evaluated (unstable cases reported separately).
- Sensitive-field retention = sensitive fields sent / sensitive fields total. Reduction = 1 - retention.
- Over-redaction = required categories given an action outside the acceptable set / required categories.
- Under-redaction = non-required sensitive categories the planner KEPT / non-required sensitive categories.
- Label agreement (secondary) = planner action in acceptable_actions / non-ambiguous categories.
- Decision consistency = (case, category) decisions identical across the 3 runs / all decisions.
- Detection recall = planted items found / planted items (from corpus/planted.json).
- Trap check = in trap cases the identity categories are kept, and in the matching non-trap cases they are not.

## 10. Pre-registered thresholds and decision rule (SIGN BEFORE RUNNING)
| Metric | Target | Signed value |
|---|---|---|
| Answer preservation | 90% or more | 90% |
| Sensitive-field reduction vs send-everything | 50% or more | 50% |
| Decision consistency (3 runs) | 80% or more | 80% |
| Trap check | Clear difference in decisions | Clear difference |
| Detection recall | 80% or more (else reported as the main failure) | 80% |

Decision rule:
- GO: answer preservation met and at least 3 of the other 4 met.
- GO WITH CHANGES: answer preservation met, others missed for repairable reasons (explain each).
- NO-GO: answer preservation under 70%, decisions look random, or it works only by hard-coding task rules.

If NO-GO: decide within one day between (a) narrowing to one document type with rules plus an LLM, or
(b) pivoting to the photo-based "what could a stranger infer" idea.
